# Annotator — Implementation Plan & Log

A small Rust TUI application for annotating code files. You open a file, "paint"
(select) a range of lines, write a review-style note, and the app saves the
annotation to a file named `<UUID>.md` containing the note plus metadata.

## Requirements

- Open a code file and view it in a terminal UI.
- Select ("paint") a range of lines, like a review comment.
- Write a free-text note about the selected lines.
- Save the annotation to `<UUID>.md` (UUID generated by the app).
- The saved file stores metadata in addition to the comment:
  - git commit hash (if available)
  - hash of the file contents
  - the file name
  - the lines in question (start–end range)

## Design decisions

- **UI**: Terminal UI (TUI) built with `ratatui` + `crossterm`. "Painting" lines
  maps naturally to a vim-like visual selection in the terminal.
- **Interaction model** (modal, vim-inspired):
  - `j`/`k` or arrows: move cursor
  - `V`: enter visual (paint) mode, move to extend the selection
  - `Enter` / `c`: write a note for the current selection
  - Note editor: type text, `Esc` to save, `Enter` for newline
  - `q`: quit
- **Storage**: one Markdown file per annotation, named `<UUID>.md`, written to
  an `annotations/` directory in the current working directory (configurable via `--output-dir`).
- **Metadata**: collected at save time:
  - `git rev-parse HEAD` of the repo containing the file (optional, if in a repo)
  - SHA-256 of the file contents
  - file path (as given)
  - selected line range (start, end, 1-based)
  - timestamp (UTC)
- **Output format** (`<UUID>.md`):

  ```markdown
  # Annotation

  - file: path/to/file.rs
  - lines: 12-18
  - git_commit: <hash or "unavailable">
  - content_sha256: <hash>
  - created_at: <RFC3339 UTC>

  ## Comment

  <note text>
  ```

## Dependencies

- `ratatui` + `crossterm` — TUI
- `uuid` (v4) — annotation file names
- `sha2` — content hashing
- `chrono` — timestamps

## Feedback from User Testing

Issues and feature requests collected from annotation files created during testing:

### UX Improvements (Addressed)
- **Visual mode key**: Changed from `Shift+V` to lowercase `v` (no Shift required)
- **Output location visibility**: Added `saves to: <output_dir>` in the header
- **Help text**: Clarified "V paint multiple lines" in the status bar
- **Cancel comment**: Added `Ctrl+Q` in editing mode to discard a comment without saving
- **Syntax highlighting**: Added basic Rust syntax coloring for keywords (fn, let, pub, etc.), strings, and comments (line and block)

### Feature Requests (Future)
- Support commenting entire directories or paths (recursive annotation)
- Built-in file selection/navigation
- Configurable hash scope (file vs. line range)
- Special "/exit" command to cancel editing without saving (implemented as `Ctrl+Q` instead)
